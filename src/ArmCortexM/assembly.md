# Assembly

## Stack
- its a region of memory treated as a data structure
- grows upwards (from higher to lower addresses)
- SP register points to top of register
- allocation:
    ```asm
    sub SP, SP, #40    ;allocates 10 bytes
    add Sp, SP, #40    ;deallocates 10 bytes
    ```
- PUSH and POP: instructions to directly manipulate the stack
    ```asm
    push {R4-R11, LR}   ;push register and return address into the stack
    ; ...
    pop {R4-R11, PC}    ;pop from stack and put data on registers and PC
    ```

### Stack frame
- to better access data from the stack in a function, a register (suck as R11) serves as a stack frame
- stack frame will point to the base of the stack of that specific function
- order of data allocated on stack after a function call:
    - 1. Parameters
    - 2. Return address
    - 3. Saved registers
    - 4. Local Variables
- one advantage of a stack frame is that you can push and pop while still accessing local variables correctly by their symbolic name


### Stack rules
- 1. program segments must have equal number of push and pull operations
- 2. stack acesses should not be performed in unallocated areas
- 3. stack push must first decrement by (4 * BYTES_TO_ALLOCATE)
- 4. stack pop must increment by (4 * BYTES_TO_DEALLOCATE) after reading data

## Parameter passing
- methods to pass parameters
    - call by value: makes a local copy of the data
    - call by reference: passes a pointer to the data
- by AAPCS convention, the first four parameters are passed in the R0-R3 registers  
(if more than 4 parameters: use the stack)
- in assembly: multiple return values can be passed through registers

## C compiler implementation of variables
- when working with values with less than 4 bytes (such as uint8_t), the compiler promotes/demotes this values to fit the operations
- in the example below: the compiler optimizes the multiplication with 2 additions

```C
 /* C Code - in and out are uint8_t */

 uint8_t out = (99*in) / 100;
```

```Asm
;Assembly translation of code above
;generated by the ARM Keil uVision compiler

    ldr     r1, [pc, #208]
    movs    r2, #0x64
    ldrb    r0, [r1, #0x01]     ;'in' is demoted here
    add     r0, r0, r0, lsl #5
    add     r0, r0, r0, lsl #1
    udiv    r0, r0, r2
    strb    r0, [r1, #0x02]
```

- sometimes looking at the assembly code can help visualize bugs
- example below: lsb is being added with 8 BEFORE the logic shift left

```C
 /* C Code */

 uint32_t combine(uint8_t msb, uint8_t lsb){
    return msb<<8 + lsb;
 }

```

```Asm
;Assembly translation of code above

combine
    mov     r2, r0
    add     r3, r1, #0x08   ;first: lsb + 8
    lsl     r0, r2, r3      ;second: msb<<(lsb + 8) 
    bx      lr
```

## IEEE floating-point numbers
- below is the structure of a 32-bit float:

```
[ s ] [e7..........e0] [m1................m23]

Bit 31: mantissa sign  
s = 0: positive
s = 1: negative

Bits 30-23: 8-bit binary exponent

Bits 22-0: 24-bit mantissa, expressed as a binary fraction  
a binary 1 as the most significant bit is implied
```
- the value of a single-precision floating point number is  
  
        f = (-1)^s * 2^(e - 127) * m

        where:  
        s: mantissa sign  
        e: binary exponent  
        m: mantissa  

- registers S0-S31 are 32-bit floating-point registers
- registers D0-D15 are 64-bit floating-point registers (S1 and S0 combine to form D0)
- below are listed instructions to work with these registers (SN and DN are general representations of floating-point registers, while RN are of normal ones)

```Asm
    vldr.f32    SN, [RN]        ;load 32-bit float at [RN] to SN           
    vstr.f32    SN, [RN]        ;store 32-bit SN to memory at [RN]
    vldr.f32    SN, [RN, #n]    ;load 32-bit float at [RN + #n] to SN
    vstr.f32    SN, [RN, #n]    ;store 32-bit SN to memory at [RN + #n]
    vldr.f32    SN, =const      ;load 32-bit constant into SN 
```
